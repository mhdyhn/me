# فرایند افزودن و تأیید حرکت

## ۱. افزودن یا ویرایش حرکت

1. تعریف تمرین در `src/data/exercises.ts` (با `defineExercise`) و ترجمه در `src/data/exercisePersian.ts`.
2. حرکت سه‌بعدی در `src/motion/library.ts` با پنج کلید (`0`، `0.25`، `0.5`، `0.75`، `1`).
3. اگر عضله‌ی جدیدی لازم است، ناحیه‌ی آن در `src/motion/muscles.ts` تعریف شود.
4. اجرای `npm run verify:engine`. این دستور:
   - همهٔ پیکربندی‌ها را با اسکیما بررسی می‌کند؛ هر رد شده خروجی غیرصفر می‌دهد.
   - وجود فایل مدل و امضای `glTF` را چک می‌کند.
   - نگاشت عضلات و طول حلقه را می‌نویسد.
   - `docs/engine/STATUS.md` را بازتولید می‌کند. این فایل را دستی ویرایش نکن.

## ۲. تأیید

وضعیت هر تمرین در `validation.status` ثبت می‌شود:

| وضعیت | شرط | مثال |
| --- | --- | --- |
| `unverified` | پیش‌فرض. هیچ شاهد بصری یا عددی ثبت نشده. | همهٔ ۳۲ تمرین فعلی |
| `numeric-checked` | بررسی عددی (پای معلق، فاصلهٔ دست و ابزار) ثبت شده. | بعد از بررسی |
| `visually-reviewed` | شاهد بصری (تصویر فریم یا ویدیو از رندر واقعی) ثبت و بازبینی شده. | بعد از بازبینی |

قاعده: حرکتی که بصری بررسی نشده، «تأییدشده» ادعا نمی‌شود. تغییر وضعیت به `visually-reviewed` بدون شاهد مجاز نیست. شاهد باید در مخزن ذخیره شود (مثلاً `docs/engine/evidence/<id>/`) و مسیرش در یادداشت تمرین بیاید.

## ۳. مدل‌ها و دارایی‌ها

- فقط مجوز **CC0**، **Public Domain** یا **CC-BY** با ذکر منبع. مجوزهای **NC** و **ND** و «استفادهٔ شخصی» رد می‌شوند.
- هر دارایی جدید باید در `LICENSES.md` با نام، URL، نسخه، مجوز، و تاریخ بررسی ثبت شود.
- مقدارهای فنی (اندازه، هش، تعداد استخوان) از خود فایل خوانده شوند، نه از حافظه. `npm run verify:model` هش را بررسی می‌کند.
- محتوای دارای حق‌نشر دانلود یا کپی نمی‌شود. اپ باید کاملاً آفلاین بماند.
- جایگزینی مدل یا خرید بسته‌ی تجاری فقط با تأیید صریح کاربر انجام می‌شود.

## ۴. قبل از انتشار

```bash
npx tsc -b && npm test && npm run build && npm run build:offline && npm run verify:offline && npm run verify:engine
```
